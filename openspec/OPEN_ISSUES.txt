1. 怪物战斗档案与骰式工具（最小闭环依赖，顺序 1/6）

目标：怪物词表从"只有 speed"扩展到战斗档案，出生时掷出生命上限并挂
HitPoints。这是"六维+玩家 HP"的怪物镜像；落完后怪物成为可被打中的
对象。消费者：条目 4、5、6。变更命名建议：monster-combat-profile。

现状：
- data/core/monsters.ron 目前只有 speed 一词；文件注释已写明生命骰、
  护甲、攻击组会在这里生长。
- src/core/monster/types/monster_entry.rs 是词表布局；
  src/core/monster/resources/monster_registry.rs 是加载与校验（风格照
  race/class 注册表：错误信息带文件与条目 id）。
- src/core/monster/entities/monsters.rs 的 spawn_monsters 现在只挂 kind、
  speed、格坐标、NextTurn；health 的 HitPoints 组件已通用，但只有主角挂
  （src/core/player/entities/player.rs）。

落地内容：
- 骰式工具（本条第 1 部分；也可单独切成更小的变更）：解析 NdM
  （tome2 数据只有这种形态，无修正项），掷骰 = N 个 dM 之和；上限函数
  （N*M）等 FORCE_MAXHP 旗标进词表时再落（tome2 的 maxroll，
  src/z-rand.c:337-349）。解析错误带出错文件与条目 id。建议独立小域
  （消费者横跨怪物与战斗）。
- 词表新字段（建议现代命名）：hit_points（骰式字符串）、armor_class
  （整数）、level（整数）、blows（列表，元素含 method 与 damage 骰式）。
  speed 保留。
- 出生：掷 hit_points 得上限，挂 HitPoints { current: max, max }。
- 巨白鼠数据（tome2 lib/edit/r_info.txt:1338-1352）：
  I:110:2d2:8:7:30 -> speed 110、生命骰 2d2、视野 8、护甲 7、警觉 30；
  W:4:1:200:1 -> 等级 4、稀有度 1、尸体重量 200、经验 1；
  B:BITE:POISON:1d3 -> 咬击、中毒、1d3。
- 本变更暂不落：experience（等成长变更）、视野/警觉/稀有度/掉落/装备
  槽/法术/旗标（各自后续）。

tome2 参考：
- 词表格式说明 lib/edit/r_info.txt:122-186（I 字段 = speed:hit points:
  vision:armor class:alertness；W 字段 = level:rarity:corpse weight:
  experience；B 字段 = method:effect:damage，最多 4 行）。
- 词表解析 src/init1.c:7862-7874（I 字段，2d2 拆成 hdice/hside）、
  src/init1.c:7919-7936（W 字段）、src/init1.c:7942（B 字段）。
- 出生掷生命 src/monster2.c:2594-2605（maxhp = damroll(hdice,hside)，
  hp = maxhp；随后 2614-2615 把 r_ptr->ac 与 level 抄进个体）。

验证：坏骰式与护甲越界拒绝启动且错误信息含文件与 id；出生生命落在骰式
范围（2d2 -> 2..4）；巨白鼠条目逐值对齐。

依赖：无前置；是条目 4、5、6 的前置。

待裁决：blows 的 effect 本变更是否入表。tome2 用 effect 查"威力"决定
怪物命中值（RBE_HURT=60、RBE_POISON=5，src/melee1.c:1416-1565，判定入口
1566；巨白鼠是 POISON=5）。若不入表，首版命中威力取什么值由变更 design
定并记录。

2. 玩家战斗数值派生（最小闭环依赖，顺序 2/6）

目标：从六维与职业得出玩家的攻击值、伤害修正、护甲修正，并定义徒手
伤害档；不引入装备域与技能域。消费者：条目 4（命中/伤害）、条目 5
（护甲）。变更命名建议：combat-bonuses。

现状：Stats 六维与出生接线已就位（src/core/player/entities/player.rs）；
生命派生已有先例（src/core/health/utils/hp.rs 的 stat_bonus_index 与
src/core/health/constants/constitution_hp_bonus.rs 的 38 项表）；没有
战斗域。

落地内容：
- 四张修正表，逐值从 tome2 搬（形态照 constitution_hp_bonus；表内
  字节值以 128 为零点，取值后减 128）：
  力量到命中 adj_str_th（src/tables.c:610）、
  力量到伤害 adj_str_td（src/tables.c:518）、
  敏捷到命中 adj_dex_th（src/tables.c:564）、
  敏捷到护甲 adj_dex_ta（src/tables.c:472）。
  索引复用压缩刻度（与 stat_bonus_index 同源，tome2 的 stat_ind）。
- 合成：to_h = (adj_str_th - 128) + (adj_dex_th - 128)；
  to_d = adj_str_td - 128；to_a = adj_dex_ta - 128
  （src/xtra1.c:3482-3491）。
- 攻击值：chance = 命中技能项 + to_h * 3（src/cmd1.c:2644；
  BTH_PLUS_ADJ = 3，src/defines.h:367）。
- 命中技能项：tome2 用 skill_thn（src/xtra1.c:3903：
  50 * ((7*战斗风格 + 3*战斗) / 10) / 10），技能域不在本项目。变更
  design 必须给确定替代并记录映射。1 级战士的推导值供参考：职业数据给
  Combat 基数 2000、Weaponmastery 1000（lib/edit/p_info.txt:80-81 的
  C:k；原始值除以 1000 得技能值，src/defines.h:4573-4574 与
  src/skills.c:114），默认风格取武器掌握（src/skills.c:728-745），得
  50 * ((7*1 + 3*2) / 10) / 10 = 5。
- 徒手伤害：武器掌握风格 + 空手时固定 1 点（src/cmd1.c:2665），加 to_d
  后负值截 0（src/cmd1.c:2846-2853）；空手不掷武器骰、不参与暴击
  （暴击只在武器分支，src/cmd1.c:2743）。首版伤害 = 1 + to_d。
- 多击：tome2 的 num_blow（src/xtra1.c:3600-3660）首版不做，单次攻击；
  随装备变更再落。
- 玩家护甲：怪物命中玩家读 ac + to_a（src/melee1.c:1394）；无装备时
  ac = 0，to_a 来自敏捷表。
- 出生接入：在 spawn_player 算好（挂组件或按需算，design 裁）。

验证：四张表逐值测试；出生后的 to_h/to_d/to_a 手算一致；徒手伤害负
修正截 0。

依赖：无前置；与条目 1 互不依赖；是条目 4、5 的前置。

待裁决：命中技能项的替代规则；数值出生固化还是读取时计算（装备落地前
都静态）。

3. 伤害通道与死亡（最小闭环依赖，顺序 3/6）

目标：一条"对任意生物施加伤害"的通道与归零处理，让扣血、怪物移除、
主角死亡可独立测试；生产者等条目 4、5 接入。变更命名建议：
damage-and-death。

现状：HitPoints { current, max } 已存在
（src/core/health/components/hit_points.rs；字段注释标注等战斗系统，
当前不变量只有 current <= max）；没有伤害系统；应用状态只有
MainMenu/Game（src/core/app_state.rs）。

落地内容：
- 施加伤害入口（消息或直接系统，形状由 design 定）：current -= damage；
  不夹到 0，允许负值（照搬 tome2）。
- 死亡判定为严格负值：怪物 hp -= dam，hp < 0 才死（src/xtra2.c:4550-
  4553）；主角 chp -= damage，chp < 0 才死（src/spells1.c:1368-1380）。
  即 0 点仍活着。
- 怪物死亡：实体移除（tome2 在 monster_death 收尾时 delete_monster_idx，
  src/xtra2.c:3917 与 4819）；经验、掉落、尸体押后（经验归成长变更）。
- 主角死亡：Dead 状态或标记 + 停收命令（tome2 置 death/leaving）；表现
  留给条目 6。
- 不变量：current 不高于 max；负值合法。

验证：扣减正确；0 不死；负 1 死；怪物实体被移除；主角死后命令不再执行。

依赖：无前置；是条目 4、5 的前置。

待裁决：入口形状（消息还是直接系统）；主角死后就地停住还是切状态
（AppState 已预留 MainMenu）。

4. 半环甲：玩家攻击怪物（闭环本体前半，顺序 4/6）

目标：撞向怪物格即攻击；命中、伤害、扣血、怪物死亡；玩家能打死老鼠
（怪物尚不还手）。与条目 5 合起来才是最小闭环。变更命名建议：
player-attacks。

现状与改动：
- 移动管线：MoveToCell 命令（src/core/player/commands/move_to_cell.rs）
  -> 执行器校验并寻路（src/core/player/systems/commands/move_to_cell.rs）
  -> Path 逐格 -> plan_move 计划 Move（src/core/player/systems/
  plan_move.rs）-> act_move 改格（src/core/movement/systems/act_move.rs）。
- 现行 monster spec 明说"怪物不阻碍移动、主角可穿行怪物格"
  （openspec/specs/monster/spec.md 的"主角穿行怪物所在格"场景）；
  本变更必须改这条：目标格有怪物时解析为攻击。
- 攻击与时钟：tome2 出手与移动同为 100 基准（撞怪出手在
  src/cmd2.c:1213-1226；移动在 src/cmd1.c:4672）；项目走现有
  action_duration（src/core/speed/utils/action_duration.rs）。
- 命中：chance = 玩家攻击值 + to_h * 3（条目 2 已就位）；判定照搬
  test_hit_norm（src/cmd1.c:52-75）：先掷 0..99，小于 10 时按小于 5
  定必中或必失；chance <= 0 必失；否则 rand_int(chance) < ac*3/4 判失。
  项目没有隐身与幸运：视为可见、去掉 luck 项（design 记录）。
- 伤害：徒手 1 + to_d，负值截 0（src/cmd1.c:2665、2846-2853）；怪物方
  扣血与死亡走条目 3。
- 最小反馈：怪物消失即可；动画由条目 6 补。
- 长路径撞上怪物：停下攻击还是绕行，design 裁（点击移动模型特有；
  tome2 逐格操作没有这个问题）。

验证：撞怪不改格；固定必中/必失边界；伤害区间；死亡移除；现行 spec
条款更新为"怪物阻挡玩家"语义。

依赖：条目 1、2、3。

5. 半环乙：怪物攻击主角（闭环本体后半，顺序 5/6）

目标：怪物行动到期且与主角相邻时出手；主角挨打、可能死亡；闭环在此
合拢。变更命名建议：monster-attacks。

现状与改动：
- src/core/monster/systems/plan_wander.rs 现在 75% 站住、25% 随机移动；
  本变更加最高优先分支"相邻主角 -> 攻击"，出手同样消耗一次行动
  （next_turn.at = now + action_duration(...)）。tome2 的决策：怪物要
  走进主角所在格时不移动、出手、算一回合（src/melee2.c:7138-7152）。
- 怪物命中：判定抄 check_hit（src/melee1.c:60-81）：先掷 0..99，小于
  10 时按小于 5 定必中或必失；i = power + level*3；
  randint(i - luck) > ac*3/4 则命中；ac = 玩家 ac + to_a。luck 去掉。
  power 由攻击的 effect 查表（RBE_HURT=60 等，src/melee1.c:1416-1565；
  巨白鼠是 POISON=5）——见条目 1 的待裁决。
- 伤害：掷 blow 骰（巨白鼠 1d3）；tome2 怪物伤害就是骰值，无属性修正。
- 扣血与死亡：走条目 3；主角死后停收命令。
- 相邻判定：CellCoord 与主角格比较（tome2 用 (ny,nx)==(py,px)）。

验证：相邻必出手；不相邻仍走原随机移动；必中/必失边界；伤害区间；
主角生命变负后停收命令。

依赖：条目 1、2、3；与条目 4 合起来才是最小闭环。

6. 战斗反馈：动画与生命显示（收尾，顺序 6/6）

目标：把 Attack/Hit/Die 三个动画槽位与生命显示接上，给最小闭环一个
可见的观感（PD 风格）。变更命名建议：combat-feedback。

现状：
- AnimKind 已含 Attack/Hit/Die，注释写明等战斗命令落地
  （src/frontend/display/sprite_animation/constants/anim_kind.rs:8-30）；
  形象动画与挂载在 src/frontend/display/creature 与 sprite_animation
  域；形象数据在 data/graphic/creature_figures.ron，目前只有 idle
  与移动。
- 没有血条、伤害数字、战斗消息。

落地内容（可分批）：
- 攻击动作：前冲-回弹，不必新帧；受击帧或闪烁；死亡帧或淡出。
- 伤害数字上浮（PD 风格）。
- 生命显示：主角 HUD 与怪物头顶小血条（数据来自条目 1 与既有玩家
  生命）。
- 战斗消息：tome2 是文字行，PD 用漂浮数字；做哪一种或并存，design 裁。

依赖：事件源来自条目 4、5；帧素材与显示组件可提前做。

待裁决：动画帧素材来源；是否引入战斗消息系统。
