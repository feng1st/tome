一、最小战斗闭环（按序 1/6 – 6/6）

总目标：玩家与怪物能互相攻击致死，前端看得见。取材按 config.yaml 的
迭代取材原则：每个终局公式只落基础项与支撑系统已存在的项；缺项用
设计定死的固定值顶替，并在 design 里记录顶替值与终局来源的映射
（回收顶替值的扩展条目见第二部分）。

已存在的支撑系统（取材依据）：六维与出身修正、玩家生命派生、
HitPoints 组件、速度域与世界时钟、移动管线、怪物词表与出生、怪物
随机移动、前端动画槽位（Attack/Hit/Die 已预留）。
不存在的支撑系统（本次一律不取）：技能、装备、状态、effect 家族、
旗标、感知 AI、经验/成长、消息。

顺序理由：1、2、3 互不依赖，但都先于 4、5；6 收尾。

1. 怪物战斗档案与骰式工具（顺序 1/6）

目标：怪物词表从"只有 speed"扩展出战斗档案，出生时掷出生命上限并挂
HitPoints。消费者：条目 4、5、6。变更命名建议：monster-combat-profile。

现状：
- data/core/monsters.ron 目前只有 speed 一词；文件注释已写明生命骰、
  护甲、攻击组会在这里生长。
- src/core/monster/types/monster_entry.rs 是词表布局；
  src/core/monster/resources/monster_registry.rs 是加载与校验（风格照
  race/class 注册表：错误信息带文件与条目 id）。
- src/core/monster/entities/monsters.rs 的 spawn_monsters 现在只挂 kind、
  speed、格坐标、NextTurn；health 的 HitPoints 组件已通用，但只有主角挂
  （src/core/player/entities/player.rs）。

落地内容：
- 骰式工具（可单独切成更小的变更）：解析 NdM（tome2 数据只有这种形态，
  无修正项），掷骰 = N 个 dM 之和。解析错误带出错文件与条目 id。建议
  独立小域（消费者横跨怪物与战斗）。上限函数不做——FORCE_MAXHP 属旗标
  系统，不存在（见条目 7）。
- 词表新字段（建议现代命名）：hit_points（骰式字符串）、armor_class
  （整数）、level（整数）、blows（列表，元素先只含 damage 骰式）。
  speed 保留。blows 元素是否给 method/effect 预留空位由 design 裁
  （tome2 是 method:effect:damage 三元组；effect 家族见条目 10）。
- 出生：掷 hit_points 得上限，挂 HitPoints { current: max, max }。
- 巨白鼠数据（tome2 lib/edit/r_info.txt:1338-1352）：
  I:110:2d2:8:7:30 -> 取 speed 110（已有）、生命骰 2d2、护甲 7；
  W:4:1:200:1 -> 取等级 4；
  B:BITE:POISON:1d3 -> 只取伤害骰 1d3，effect（POISON）不入数据
  （effect 家族不存在，见条目 10）。
  感知 8（aaf）、睡眠 30 不入表（见条目 11）；稀有度不入表（见条目 7）；
  尸体重量、经验 1 不入表（见条目 13、12）。

tome2 参考：
- 词表格式说明 lib/edit/r_info.txt:122-186。
- 词表解析 src/init1.c:7862-7874（I 字段，2d2 拆成 hdice/hside）、
  src/init1.c:7919-7936（W 字段）、src/init1.c:7941-8000（B 字段）。
- 出生掷生命 src/monster2.c:2594-2605（maxhp = damroll(hdice,hside)，
  hp = maxhp；随后 2614-2615 把 r_ptr->ac 与 level 抄进个体）。
- damroll 在 src/z-rand.c:337-343。
- 语料库交叉：.ref/tome2-specs/specs/monster/spec.md（词表格式）、
  rng/spec.md（掷骰）、monster-generation/spec.md（出生抄录）。

验证：坏骰式拒绝启动且错误信息含文件与 id；出生生命落在骰式范围
（2d2 -> 2..4）；巨白鼠条目逐值对齐。

依赖：无前置；是条目 4、5、6 的前置。

2. 玩家战斗数值派生（顺序 2/6）

目标：从六维得出玩家的命中修正、伤害修正、护甲修正，定义徒手伤害
基础值；命中技能项用固定值顶替。消费者：条目 4（命中/伤害）、
条目 5（护甲）。变更命名建议：combat-bonuses。

现状：Stats 六维与出身接线已就位（src/core/player/entities/player.rs）；
生命派生已有先例（src/core/health/utils/hp.rs 的 stat_bonus_index 与
src/core/health/constants/constitution_hp_bonus.rs 的 38 项表）；没有
战斗域。

落地内容（附终局公式与本次取材边界）：
- 四张修正表，逐值从 tome2 搬（形态照 constitution_hp_bonus；表内
  字节值以 128 为零点，取值后减 128）：
  力量到命中 adj_str_th（src/tables.c:610）、
  力量到伤害 adj_str_td（src/tables.c:518）、
  敏捷到命中 adj_dex_th（src/tables.c:564）、
  敏捷到护甲 adj_dex_ta（src/tables.c:472）。
  索引复用压缩刻度（与 stat_bonus_index 同源，tome2 的 stat_ind）。
- 合成：to_h = (adj_str_th - 128) + (adj_dex_th - 128)；
  to_d = adj_str_td - 128；to_a = adj_dex_ta - 128
  （src/xtra1.c:3482-3491）。
- 攻击值：chance = 命中技能顶替值 + to_h * 3。终局公式是
  chance = skill_thn + bonus * 3（src/cmd1.c:2640-2644；
  BTH_PLUS_ADJ = 3，src/defines.h:367），其中：
  - skill_thn 依赖技能系统（不存在）-> 固定值顶替，design 定并记录
    映射（终局来源 src/xtra1.c:3903：50 * ((7*战斗风格 + 3*战斗) / 10)
    / 10；1 级战士推导值供参考：职业数据给 Combat 基数 2000、
    Weaponmastery 1000（lib/edit/p_info.txt:80-81 的 C:k；原始值除以
    1000 得技能值，src/skills.c:114），默认风格取武器掌握
    （src/skills.c:728-745），按源码逐步整数除法得 5——语料库把公式
    合并记为 /100，会得 6，以源码为准）。由条目 8 回收顶替值。
  - bonus = to_h + to_h_melee + 武器 to_h；后两项依赖技能/装备
    （不存在），值为 0，不实现，公式位置在 design 记录（终局来源
    src/xtra1.c:3740-3746、2331-2372；战斗技能按 scale(10) 加 to_d
    同理，src/xtra1.c:3748-3754）。由条目 8、9 回收。
- 徒手伤害基础值 1（src/cmd1.c:2665）：伤害 = 1 + to_d，负值截 0
  （src/cmd1.c:2846-2853）。武器骰与暴击只在武器分支
  （src/cmd1.c:2743），装备系统不存在，不实现。
- 玩家护甲：怪物命中读 ac + to_a（src/melee1.c:1394）；无装备时
  ac = 0，to_a 来自敏捷表。
- 出生接入：在 spawn_player 算好（挂组件或按需算，design 裁）。

不做（支撑系统不存在）：暴击五档（src/cmd1.c:123-186，见条目 9）、
多击 num_blow（src/xtra1.c:3600-3660，见条目 8、9）、站姿与移动
姿态表（src/tables.c:2875-2965，见条目 9）。

验证：四张表逐值测试；出生后的 to_h/to_d/to_a 手算一致；徒手伤害负
修正截 0。

依赖：无前置；与条目 1 互不依赖；是条目 4、5 的前置。

语料库交叉：.ref/tome2-specs/specs/player-derive/spec.md、
tables/spec.md、player-melee/spec.md。

3. 伤害通道与死亡（顺序 3/6）

目标：一条"对任意生物施加伤害"的通道与归零处理，让扣血、怪物移除、
主角死亡可独立测试；生产者由条目 4、5 接入。变更命名建议：
damage-and-death。

现状：HitPoints { current, max } 已存在
（src/core/health/components/hit_points.rs；当前不变量只有
current <= max）；没有伤害系统；应用状态只有 MainMenu/Game
（src/core/app_state.rs）。

落地内容：
- 施加伤害入口（消息或直接系统，形状由 design 定）：current -= damage；
  不夹到 0，允许负值（照搬 tome2）。
- 死亡判定为严格负值：怪物 hp < 0 才死（src/xtra2.c:4550-4553）；
  主角 chp < 0 才死（src/spells1.c:1368-1380）。即 0 点仍活着。
- 怪物死亡：实体移除（tome2 由 mon_take_hit 收尾时 delete_monster_idx
  移除，src/xtra2.c:4819）。
- 主角死亡：Dead 状态或标记 + 停收命令（tome2 置 death/leaving）；
  表现留给条目 6。
- 不变量：current 不高于 max；负值合法。

不做（支撑系统不存在）：经验（见条目 12）、掉落与尸体（见条目 13）、
怪物恐惧掷点（见条目 11）、墓碑与收尾（见条目 13）。

验证：扣减正确；0 不死；负 1 死；怪物实体被移除；主角死后命令不再
执行。

依赖：无前置；是条目 4、5 的前置。

待裁决：入口形状（消息还是直接系统）；主角死后就地停住还是切状态
（AppState 已预留 MainMenu）。

语料库交叉：.ref/tome2-specs/specs/monster-death/spec.md、
death-score/spec.md（墓碑与收尾）。

4. 半环甲：玩家攻击怪物（顺序 4/6）

目标：撞向怪物格即攻击；命中、伤害、扣血、怪物死亡；玩家能打死老鼠
（怪物尚不还手）。与条目 5 合起来才是最小闭环。变更命名建议：
player-attacks。

现状与改动：
- 移动管线：MoveToCell 命令（src/core/player/commands/move_to_cell.rs）
  -> 执行器校验并寻路（src/core/player/systems/commands/move_to_cell.rs）
  -> Path 逐格 -> plan_move 计划 Move（src/core/player/systems/
  plan_move.rs）-> act_move 改格（src/core/movement/systems/act_move.rs）。
- 现行 monster spec 明说"怪物不阻碍移动、主角可穿行怪物格"
  （openspec/specs/monster/spec.md 的"主角穿行怪物所在格"场景）；
  本变更必须改这条：目标格有怪物时解析为攻击。
- 攻击是独立行动（不是移动的副产品），归属域由 design 裁（建议独立
  combat 域：生产者横跨玩家与怪物）；定价走现有 action_duration
  （src/core/speed/utils/action_duration.rs），与移动同基准（tome2
  出手与移动同为 100，src/cmd2.c:1213-1226、src/cmd1.c:4672）。
- 命中判定骨架（基础项，照搬 test_hit_norm，src/cmd1.c:52-75）：
  先掷 0..99，小于 10 时按小于 5 定必中或必失；chance <= 0 必失；
  否则 rand_int(chance) < ac*3/4 判失（rand_int 出 0..chance-1，
  src/z-rand.h:30-62）。chance = 命中技能顶替值 + to_h * 3
  （条目 2）；ac = 怪物 armor_class（条目 1）。隐身与幸运系统不存在：
  视为可见、无 luck 项（design 记录）。
- 伤害：1 + to_d，负值截 0（条目 2）；扣血与死亡走条目 3。
- 长路径撞上怪物：停下攻击还是绕行，design 裁（点击移动模型特有；
  tome2 逐格操作没有这个问题）。
- 最小反馈：怪物消失即可；动画由条目 6 补。

不做（支撑系统不存在）：武器骰与暴击（见条目 9）、多击（见条目 8、
9）、伤害措辞档位（见条目 14）。

验证：撞怪不改格；固定必中/必失边界；伤害区间；死亡移除；现行 spec
条款更新为"怪物阻挡玩家"语义。

依赖：条目 1、2、3。

语料库交叉：.ref/tome2-specs/specs/player-melee/spec.md。

5. 半环乙：怪物攻击主角（顺序 5/6）

目标：怪物行动到期且与主角相邻时出手；主角挨打、可能死亡；闭环在此
合拢。变更命名建议：monster-attacks。

现状与改动：
- src/core/monster/systems/plan_wander.rs 现在 75% 站住、25% 随机移动；
  本变更加最高优先分支"相邻主角 -> 攻击"，出手同样消耗一次行动
  （next_turn.at = now + action_duration(...)）。tome2 对应决策：怪物
  要走进主角所在格时不移动、出手、算一回合（src/melee2.c:7138-7152）。
- 怪物命中判定骨架（基础项，照搬 check_hit，src/melee1.c:60-81）：
  先掷 0..99，小于 10 时按小于 5 定必中或必失；i = power + level*3；
  randint(i) > ac*3/4 则命中（randint 出 1..M，src/z-rand.h:30-62）；
  ac = 玩家 ac + to_a（条目 2），level = 怪物 level（条目 1）。
  luck 项不存在，去掉。
- power 顶替值：终局来源是 effect 威力表（RBE_HURT=60、RBE_POISON=5，
  src/melee1.c:1416-1565），effect 家族系统不存在 -> 固定值顶替，
  design 定并记录映射（参考：基础家族 HURT=60；老鼠原版 effect 值 5
  仅作参考，不入数据）。由条目 10 回收顶替值。
- 伤害：掷 blow 伤害骰（老鼠 1d3，条目 1）；无属性修正、无 effect
  附加。
- 扣血与死亡：走条目 3；主角死后停收命令。
- 相邻判定：CellCoord 与主角格比较（tome2 用 (ny,nx)==(py,px)）。

不做（支撑系统不存在）：effect 附加如中毒、护甲折减（挂在 effect
家族分支，见条目 10）、豁免链（闪避/神力/护符，见条目 8）、命中
暴击（割伤/击碎转流血/眩晕，见条目 10）、感知/睡眠/追击/逃跑
（见条目 11）。

验证：相邻必出手；不相邻仍走原随机移动；必中/必失边界；伤害区间；
主角生命变负后停收命令。

依赖：条目 1、2、3；与条目 4 合起来才是最小闭环。

语料库交叉：.ref/tome2-specs/specs/monster-melee/spec.md。
