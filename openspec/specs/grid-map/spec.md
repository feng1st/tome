# grid-map Specification

## Purpose
定义格子化的地图数据模型与地形注册表：tile 坐标系、由数据文件定义的地形类型与标志位属性，作为渲染、寻路和移动的共同基础。

## Requirements

### Requirement: 格子地图模型

游戏 SHALL 用固定宽高的二维格子数组表示局部地图，每格存储一个地形引用；地形类型由数据注册表定义（见"地形数据注册表"）。某格可通行当且仅当其地形带 PASSABLE 标志；越界查询 MUST 视为不可通行。

#### Scenario: 查询格子可通行性

- **WHEN** 系统查询某格是否可通行
- **THEN** 该格地形带 PASSABLE 标志（如地板）时返回可通行，不带（如墙、水）时返回不可通行，越界格返回不可通行

### Requirement: 地形数据注册表

地形的种类与属性 SHALL 由数据文件定义：每个地形具有字符串 id 与一组标志位（PASSABLE、LIQUID）。代码 MUST NOT 包含地形枚举或针对具体地形 id 的逻辑分支；游戏逻辑 MUST 只通过标志位查询地形属性。新增地形 MUST 只需新增数据条目。

#### Scenario: 按标志位查询属性

- **WHEN** 游戏逻辑需要判断某格是否可通行、是否为液体
- **THEN** 结果由该格地形的标志位给出，与地形的具体 id 无关

#### Scenario: 新增地形不改代码

- **WHEN** 在地形数据文件中新增一个地形条目，并在地图文件中引用它
- **THEN** 不改动任何代码即可加载并使用该地形

### Requirement: 地图数据文件

固定地图 SHALL 由数据文件描述：legend 表将字符映射到地形 id，rows 以字符逐行铺出地图内容。地图的宽 MUST 等于 rows 中各行的长度，高 MUST 等于行数。游戏启动时 SHALL 加载测试房间数据文件，并将其作为当前地图进入游戏。

#### Scenario: 从文件解析地图

- **WHEN** 加载一个 rows 为 32 行、每行 48 个字符的地图文件
- **THEN** 得到 48×32 的格子数组，每个字符格按 legend 解析为对应地形

### Requirement: 地图数据校验

地图与地形数据文件 MUST 在加载时校验。行宽不齐、出现 legend 未覆盖的字符、引用地形注册表中不存在的 id，SHALL 导致启动失败并给出指明出错文件与位置的错误信息。

#### Scenario: 非法数据拒绝启动

- **WHEN** 地图文件引用了地形注册表中不存在的地形 id
- **THEN** 启动失败，错误信息指明出错文件与出错位置

### Requirement: 房间边界

测试房间 SHALL 大于游戏窗口的世界像素尺寸，且四周由不可通行的地形格封闭，主角无法离开房间。

#### Scenario: 边界墙阻挡

- **WHEN** 主角尝试以房间边缘墙格外侧为目标移动
- **THEN** 寻路失败或路径终止于墙格之前，主角停留在房间内

### Requirement: 水域障碍

测试房间 SHALL 包含一个内部水池障碍区域，使部分地板格之间的直线路径被阻断。

#### Scenario: 绕行水池

- **WHEN** 主角当前位置与目标格之间的直线被水池阻断
- **THEN** 存在一条绕过水池的可通行格子路径
