# Proposal: world-clock

## Why

游戏目前没有世界时钟：主角实时自由移动，怪物出生即定格——没有速度、没有行动频率、没有时间概念，怪物行动、战斗、状态等一切战术机制都无依附。词表数值要对齐 tome2（r_info 的 speed 等字段以时钟为前提），OPEN_ISSUES 原条目 1 预登记的"速度 = 行动频率"准则也在等这块地基落地。

## What Changes

- 引入**门控世界时钟**：游戏时间由主角的行动驱动——主角有行动在进行（移动，以及未来的长动作、麻痹等受迫耗时）则世界运转，无则世界冻结；冻结只冻世界逻辑与位置插值，idle 动画照播。
- **行动点连续累积**：一切生物的行动点随帧 delta 按速率连续累积，每满 100 点为一次行动边界，跨越时扣除、余数留存。帧率抖动与速度中途变化都不引入误差。
- **位置是行动点账本的纯函数**：逻辑位（`CellCoord`，整格，只在行动边界翻转，一切判定只读它）与呈现位（`Position`，逻辑位 + 进度向承诺格的插值）分离；不另起动画时钟，不积压、不漂移。
- **速率数值对齐 tome2**：词表 speed 直写 tome2 原值（110 = 标准），按 extract_energy 等效表换算累积速率；速度影响累积速率，行动消耗固定 100 点。斜线移动与直线同价（tome2/PD 原样）。
- **主角与世界解耦**：主角步进不读任何怪物状态，匀速由结构保证；主角每帧的累积量发布为世界时钟，怪物按速率比值同步累积——速度肉眼可见。
- **老鼠成为第一个时钟消费者**：按 tome2 RAND_25 旗标语义随机移动——每个行动边界 25% 随机选一个方向、75% 原地不动；位移承诺带预判，世界剩余量不足以走完的格不发起。
- 词表：`monsters.ron` 条目增 `speed` 字段（老鼠 110）；主角固定标准速率，不立词表字段。不做显式"等待"动作（无需求，门控结构预留多源）。
- OPEN_ISSUES 原条目 1 随之删除（渲染侧已由直出管线解决，设计侧由本模型兑现）。

## Capabilities

### New Capabilities

- `world-clock`：门控游戏时钟——行动点模型与速率表、主角驱动与同步累积、冻结语义、位置推导、行动边界决策与预判。

### Modified Capabilities

- `hero-movement`：主角步进即世界时钟——帧 delta 连续累积，满 100 点走一步；每帧累积量与路径剩余量发布为世界时钟；逻辑位置组件分离。移动手感（寻路、逐格平滑、步长时长）不变。
- `monster`：词表增 speed 字段；怪物入时钟——行动点累积、RAND_25 边界决策、预判、逻辑位边界翻转、呈现位插值。"怪物不阻碍移动"等既有行为不变。

## Impact

- 新增 `src/core/time/` 域：行动点组件、速率表常量、世界时钟资源、同步累积系统；编排在 `core/` 根模块的 CorePhase 链中排序。
- `movement` 域：`CellCoord` 复用为逻辑位组件（自 map/types 挪入 components/）；新增 `Heading` 承诺格组件与 `interpolate` 呈现位推导系统；`follow_path` 维护主角双层位置并发布世界时钟。
- `monster` 域：出生解析 speed 入组件；`wander` 边界决策系统。
- 新增 `src/core/random/` 域：可种子化随机流资源。
- `display` 前端：`sync_animation` 读 `Heading` 切换走/停动画与朝向。
- 数据：`data/core/monsters.ron` 条目增 `speed` 字段。
- 依赖：引入 `rand` crate。
- 文档：`openspec/OPEN_ISSUES.txt` 原条目 1 删除；新条目登记 race 词表终局拆分待定。
- 终局方向（记录于 design.md）：race/class/monster 三表字段对齐 tome2 的 player_race/player_class/r_info，终值 = kind 束 + race 修正 + class 修正，出生期合成入组件；词表层不对称、运行期组件对称。
